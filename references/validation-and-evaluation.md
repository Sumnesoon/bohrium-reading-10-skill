# 验证、对照与创新边界

## 验证分层

| 层次 | 指标 | 证据来源 | 解释边界 |
|---|---|---|---|
| 对得上 | 章节覆盖率、无归属笔记数、切分依据完整率 | 章节树与原目录/标题人工核对 | 自动章节候选不等于正确章节 |
| 留得住 | 六要素齐全率、前提条件完整度、结果与结论分离 | 实际卡片和原文抽查 | 完整性需语义确认 |
| 找得回 | 锚点有效率、页码准确率、引句匹配率 | `validation_report.json` | 匹配只证明位置，不证明支持关系 |
| 用得上 | JSON 合法率、稳定 ID、跨篇同字段比较可用性 | 卡片、JSONL、可读笔记 | 不能只做视觉排版比较 |
| 可靠性 | 重复运行结构一致性、异常处置成功率 | 重复运行日志 | 不把单次成功当作稳定能力 |
| 增益 | 上述指标差值、实际耗时和真实请求数 | 同任务、同材料、同预算对照 | 本地对照不等于平台正式评分 |

## 最小对照设计

使用合法的公开论文建立开发测试集，至少覆盖：

- 常规单栏英文论文；
- 双栏论文；
- 长篇或图表较多论文；
- 扫描件、加密文件或人工构造的故障输入（必须标明为测试输入）。

对同一论文、同一任务、同一材料与可比预算，分别运行基础 Agent 和加载本技能的 Agent，记录：

- 任务完成和契约字段；
- 六要素与条件覆盖；
- 锚点有效率和错误页码；
- 人工发现的科学内容错误；
- 实际耗时与真实请求数（工具不提供时标为未测量）；
- 失败案例与部分输出。

每个条件重复运行时保留每次结果，不能只选最好的一次。公开论文测试和生成的笔记必须标明为开发示例，不能冒充平台固定案例或白板。

## 可机器判定与必须人工确认

机器可判定：JSON 合法性和类型、ID 唯一性、契约必填字段与非空性、章节标题/引句/区块/页界一致性、关键结果来源绑定、页码范围、规范化文本/OCR 引句匹配、渲染文件及视觉复核字段、数值单位归一后的位置关系、真实墙钟预算。

v1.2 新增三类机器检查：

- `section_completeness`：把「区块标题候选（含连续字母附录标题）+ PDF 大纲」与 `sections.json` 比对，有真实标题候选未入树就告警——用于抓住“漏 10 节仍能过校验”的旧漏洞；
- `status_semantics`：状态与内容语义矛盾（`not_reported` 却引用附录/作者承认的限制，或 `reported` 却写“未报告”，`conflict` 只有单锚点）；
- 请求账本：`request_ledger.jsonl` 超过 64 条即阻断，`status` 报告已用/剩余与来源（`ledger`/`native`/`unknown`），未知不写 0。

`errors` 为阻断错误，`warnings` 为未复核问题，`resolved_warnings` 保留有审阅人和理由的决定，`informational` 记录不需要复核的提示（如长参考文献页码跨度、宽松的数量词候选）。请求 `success` 须同时满足零阻断错误与零未复核警告；达到 900 秒仍强制部分完成；700 秒起给出 `deadline_warning`。

必须语义确认：章节归属、论证承接、引句支持关系、数值与实验条件对应、结论强度、作者局限、术语归一。

## 与已有摘要方案和笔记模板的边界

本技能不以通用摘要模板为目标。它的可验证增量限定在：

1. 章节树保留切分依据，笔记与真实章节显式关联；
2. 六要素由带来源的笔记汇总，结果、结论与作者限制分离；
3. 每条关键笔记具有可机器检查的页码和引句；
4. 原始文本与规范化文本分开，匹配规则固定且可复核；
5. 机械检查和语义检查分别报告，未报告和处理失败不补造。

本技能不承诺：

- 完美恢复所有 PDF 版面；
- 自动证明科学结论正确；
- 可靠识别所有扫描件、图中数据或公式；
- 在没有原始材料时补全信息；
- 替代平台正式对照、组织方评审或领域专家判断。

只有真实对照支持时，才能声称某项能力相对基础 Agent 有改进。
