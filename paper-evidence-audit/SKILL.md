# Paper Evidence Audit

从实际材料回答任务，按论文论证顺序写可复用笔记。优先完成要求明确、可以独立核查的关键结果。Python 3.10+，包含 PyPDF2。布局优先使用平台解析工具或 PyMuPDF。纯 Python 兜底的标题和双栏顺序需要复核。

## 启动

先试一次 Python shell 与工作目录写入。失败时使用已有平台解析工具；同一权限或工具错误不重复尝试，不修改 ACL。无法读取材料时保存失败原因并交接。模型不支持视觉时，不反复发送图片；可用布局文本或 OCR 读取标签，但不可据此声称已经观察到曲线或面板趋势。

1. 读取实际任务、`case.json` 和资源清单。Harbor 以 `/input/case.json`、`/input/task.md` 为入口，安装位置为 `/skills/weekly-skill`。本地 DSH 用 skill 工具报告的资源目录定位脚本。脚本命令中的 `$S` 指该目录。
2. 按 [运行手册](references/runtime.md) 执行 `audit.py prepare`，立即保存带原因的部分结果。读生成的 `contract.json` 和 `case_context.json`，确认必填字段、类型、材料清单和路径。输入任务范围与资源描述冲突时，以原始材料及实际任务为准。
3. 对实际 PDF 执行一次 `notes_tool.py extract`，复用抽取结果。抽取成功后工具会自动保存一条带精确页码和原文的 `preliminary_evidence` 检查点；它只是可恢复的真实证据，不代表任务已完成。后续批次可保留它，也可在语义笔记已经覆盖同一证据后替换。先用 `audit.py find --term ...` 批量找任务指标、条件和图表，再用 `audit.py read --page N` 读取有限原文。不要直接输出完整 pages.jsonl、blocks.jsonl 或脚本源码。仅当章节结构缺失或不可靠时运行 `index`，按任务覆盖范围修订真实章节，不逐条审查无关书签。多材料各用一个工作目录并保留来源文件。

## 写作与复核

- 按原章节组织笔记与实际论证顺序。方法、结果、结论、局限的关系用原文证据解释。按 [运行手册](references/runtime.md) 的字段交付研究问题、数据、方法、结果、结论和局限。任务未要求整篇覆盖时，说明报告范围。
- 用 `sections` 的本地帮助核对、修订真实标题。书签页只作提示，以实际页面标题确认。双栏、表格和公式的文本可能串行，优先用布局保真的后端或渲染原页。无可核验证据时保留不确定性。
- 数值结果保留对象、条件、单位、统计口径、比较组。凡答案引用编号表中的定量结果，必须写 `table_bindings.json`。严格采用“一变量、一列单元格、一个标量 claim、一个 binding”：`claim_id` 必须直接指向该单元格的标量值，不能指向同时包含多个变量或多列数值的长文本；`variable` 必须和实际 `row` 的完整数学表达式一致，并填写 `unit`。同一行的两列比较需要两个不同的 `claim_id`，共享同一完整行转录。任务明确点名的每个表格变量都必须有完整表达式完全一致的行绑定；相关量、归一化量或派生量不能替代。不能把短变量当作复合变量的前缀。凡答案引用编号图，必须写 `figure_bindings.json`，保存完整横纵轴表达式和来源。绑定无法通过时把该值或趋势标为未核验，不可猜测或自动填充。格式见 [证据手册](references/evidence.md)。
- 抽取后的自动证据检查点应在 180 秒内出现；立刻确认输出已包含非空 `structured_notes`，不要把初始化空壳算作有效交付。随后每找到 2–4 条可回链事实就用 `audit.py checkpoint --batch batch.json` 同时保存笔记、答案片段和证据绑定；不要先编写一次性组装脚本。每批只覆盖一个任务问题或一组相关结论，不等待全篇脚本或最终答案。未完成字段保留缺项说明，不用程序从笔记猜答案。
- checkpoint 同时校验契约、表格和笔记，输出简短计数；只读取报告中与本批有关的错误。短引句直接复制抽取原文，不凭记忆重写，不为消除告警伪造引句。重复出现的相同问题集中修正一次。最终仍需复核内容语义，机械回链通过不代表推论成立。
- 方法说明核对仪器、数据版本、处理流程和似然的对应关系，区分当前基线与历史比较。图形结论必须定位真实面板、完整横纵轴和比较对象；图注未陈述的趋势需要实际看图。来自正文的推论标为正文证据，不能冒充图中直接观察；视觉不可用则明确暂未核验。用 PDF 书签或实际标题检查任务引用页的上级章节；模型扩展、外部数据比较、方法和结果按真实标题归属，不因当前粗粒度章节树而错放。checkpoint 会在 outline 唯一对应时自动修正 `section_id`；没有唯一目标时会拒绝整批写入，必须先用 `notes_tool.py sections split/rename` 修复任务相关章节树，不能用 `cross_section_reason` 绕过明显错归。
- 首批可回链答案写完后保存 checkpoint。结束时执行 `audit.py finish`，全部要求完成且解决结构错误和证据告警时使用 `finish --complete`。表格抽取缺行、错序或符号损坏时，优先尝试可用的布局提取或原页渲染，查验相邻行与全部列标题后再写表格绑定。保留 `result.json`、`notes.md`、`validation_report.json` 和 `acceptance.json`。如任务要求可编辑文件，同时交付实际文件和真实渲染预览。

Harbor 预算为 64 次模型请求、900 秒、单次回复最多 16384 token。批量读取候选证据，先交付可核验部分，最后完善非核心章节。没有模型或平台轨迹时，按可复核的实际运行记录描述结果。此 Skill 的常规运行在当前会话内完成。

以实际任务预算为准：最迟 180 秒保存首份有内容的检查点；最后 20% 留给修正和最终组装。checkpoint 只保存快照，不能冻结总计时；只有 finish 冻结真实总耗时。接近预算时停止扩展非必要检索，交付已有结果与明确缺项。不要为了流程完整而重复抽取、全文重读、逐字段单独调用或制作任务未要求的图。只在用户要求时提交或发布结果。
