# 字段字典与判定方式

## 论文卡片六要素

| 字段 | 含义 | 必需内容 | 判定方式 |
|---|---|---|---|
| `research_question` | 作者试图解决的问题 | 问题、研究对象、必要背景 | 字段/来源由脚本检查；语义由人工或模型复核 |
| `data` | 数据、样本、材料或实验对象 | 来源、规模、版本、划分；未报告须说明检索范围 | 数值存在性可机器辅助；归属需语义复核 |
| `method` | 方法与成立条件 | 步骤、模型、参数、环境、对照和必要条件 | 覆盖与数值可机器辅助；完整性需语义复核 |
| `results` | 实验或分析观察到的事实 | 指标、数值、单位、对象、比较条件、负向结果 | 引句与数值位置可机器辅助；解释归属需复核 |
| `conclusion` | 作者根据结果作出的解释 | 结论、适用范围、限定强度 | 必须有来源；不能由脚本自动判为正确 |
| `limitations` | 作者明确报告的限制 | 原文限制及具体失效场景 | 作者观点与分析者推断必须分开 |

可复用的空白结构见 `assets/paper_card.template.json`；运行时由 `init` 在工作目录生成同结构文件，填写的是实际论文内容，不修改模板本身。

## 字段公共结构

```json
{
  "status": "reported",
  "content": "由实际论文支持的内容",
  "source_note_ids": ["note_0001"],
  "searched_scope": "仅 not_reported 时必填：实际检查过的章节和材料"
}
```

- `reported`：材料明确报告，需要来源笔记。
- `not_reported`：只能在明确的检索范围内声明，不能证明全文绝对没有。
- `uncertain`：材料存在但不能可靠判断，说明原因。
- `conflict`：材料之间存在冲突，逐项保留来源。
- `unresolved`：只用于运行中的占位，不允许以成功状态交付。

### 状态判定示例（v1.2 校验器会自动检查这些矛盾）

| 情形 | 正确状态 | 说明 | 触发的检查 |
|---|---|---|---|
| 原文有 “Limitations” 段，列出三条具体失效场景 | `reported` | 直接摘录并回链 | — |
| 原文没有 Limitations 段，但 Broader Impact/附录明确写了“可能含偏见”“该子任务未处理” | `reported` | 这些是作者自己声明的限制，不是分析者推断 | `status_semantics`：`not_reported` 却引用附录/作者承认时告警 |
| 检索了全文，确实没有任何限制性表述 | `not_reported` | 必须写 `searched_scope`，且内容不得再引用“附录 E 承认……” | `status_semantics` |
| 正文说 17%，表格是 11.7% | `conflict` | 至少两条锚点分别指向两处，不自行裁决 | 单锚点的 `conflict` 会告警 |
| 只看到“约”或图表模糊，无法确定数值 | `uncertain` | 写清无法判断的原因 | — |
| 作者只说“未来可改进”，没有说现有限制 | 不要写 `not_reported` 的“限制”笔记 | 这是展望，不是限制 | — |

常见错误：把“作者没有单列 Limitations 章节”当成 `not_reported`，但同一段又列出附录里的明确限制——校验器会要求改成 `reported` 或删掉该段。

## 逐节笔记字段

| 字段 | 机器判定 | 语义复核要求 |
|---|---|---|
| `note_id` | 非空且唯一 | 稳定供其他笔记、卡片和跨篇比较引用 |
| `section_id` | 必须存在于章节树 | 章节归属是否合理需复核 |
| `field` | 非空 | 应指明问题、方法、结果、概念等类型 |
| `content` | 不得为空；结构合法 | 不得超出证据，保留条件和限定词 |
| `status` | 限定枚举 | `not_reported` 必须有 `searched_scope` |
| `argument_role` | 可选字符串 | 是否有原文依据，避免套话 |
| `section_transition` | 可选对象 | 承接和引出关系是否由原文支持 |
| `anchors` | 页码有效、引句经规范化匹配 | 引句是否真正支持内容仍需语义复核 |

## 结果与过程状态

内容状态与运行状态不得混用：

- 内容状态：`reported`、`not_reported`、`uncertain`、`conflict`；
- 运行状态：`success`、`partial`，必要时按案例契约写无法判断或拒答原因。

只有实际完成全部契约且机器检查通过时才可请求 `success`。`success` 不表示语义内容经过平台或人工背书。

## 术语与缩写条目

建议字段：

- `canonical_form`：论文实际使用的主要形式；
- `surface_forms`：原文出现的缩写、大小写或同义形式；
- `expanded_form`：仅在论文明确给出时记录；
- `definition`：来自原文的定义；
- `source_note_ids`：稳定来源；
- `merge_review`：无法确认是否同义时不得合并。
